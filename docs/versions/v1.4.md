브랜치: `release/1.4` 아래 `feat/modes` · `feat/specup` → main `406fe9a`

## 패치 내역
### 공명 모드 분리
- 모드가 둘인 공명자를 모드별로 계산: 루실라(서리·에코), 에이메스(조화 파동·불꽃), 데니아(불꽃·조화 밀집), 여우의 별자리(합일·전자), 린네(조화 파동·조화 밀집)
- 모드마다 반주 효과·메커니즘·주력 에코 세트를 따로. (예전엔 두 모드 효과를 한꺼번에 받는 것으로 계산)
- 캐릭터 설정 창에서 모드를 바꿔 모드별 에코 세팅 저장. 게임과 같은 이름·아이콘. 에코 없는 모드는 체험 세팅. 기존 에코는 게임 기본 모드(첫 번째 버튼)에 남음
- 파티 편성에서 가장 좋은 모드 조합을 자동 선택(파티원·파워 서킷·이번 주기 보스 효과), 공명자 그림 왼쪽 아래에 모드 표시
- 반주 수정: 에이메스·여우의 별자리 파티 반주는 본인 제외, 루실라 서리·데니아 불꽃의 이상 효과 피해 부스트는 그 이상 효과를 거는 파티원에게, 메커니즘이 여럿인 파티원(모니에 등)의 시너지 중복 제거

### 에코 스펙업 효율
- 투자 효율 탭에 「뽑기 투자 | 에코 스펙업」 전환. 에코 칸마다 같은 코스트·주옵·세트의 새 에코를 깎았을 때 **지금보다 좋아질 확률**과 **새 에코 1개당 개인 점수 기대 상승**
- 캐릭터 설정 창 에코 카드마다 배지(더 좋을 확률 · 1개당 상승), 가장 먼저 깎을 칸은 「먼저 깎기」 + 금빛 테두리 효과
- 공효 최소치를 채우고 있으면, 바꿨을 때 최소치가 깨지는 에코는 좋아진 것으로 세지 않음(⚡)

## 고려했던 점 / 정한 것
### 모드
- 데이터: 공명자 파일의 `modes[]`에 모드별 syn·outro·sets. 공식 명칭·아이콘은 encore.moe `SkillBranches`. 새 공명자에 SkillBranches가 있으면 `modes`를 꼭 넣는다.
- CharDB `modes` / `withModes` / `setView`, 에코는 `growth.alt[모드]`.
- 파티 모드 선택(`TeamCalculator.bestModes`)은 **시너지 보너스를 뺀 강도 × 보스 효과**로 비교. 시너지를 넣으면 모드 비교가 시너지 표 쪽으로 쏠림.
- 반주 범위: "파티 전체"라도 본인 제외인 반주는 `noSelf`. 이상 효과 피해 부스트는 적 디버프가 아니라 **그 이상 효과를 거는 공명자 피해**에만.

### 스펙업 (사용자 결정)
- **에코 다시 깎기만.** 공명 체인·무기(유료)와 주파수 조정기 재구성은 제외.
- **순수 공명자 스펙만.** 파티 총점·보스·파워 서킷·파티 모드 선택을 넣지 않는다 — 주기마다 표가 달라지면 혼동.
- 효율 = 좋아질 확률 × 개인 점수(공명력·협주력) 상승률. 모드 공명자는 에코를 넣은 모드마다 따로 행.
- 공효 미달 공명자를 위로 올리지 **않는다**(ER 우선 정렬 안 함). 대신 최소치를 깨는 교체는 좋아진 것으로 세지 않음(ER 게이트).
- 확률 출처: 쿠로 게임즈 명조 한국 「상품 정보 제공」 2. 주파수 조정기 및 튜너 확률 공시 — 부옵 13종 균등·중복 없음, 수치 단계별 가중치(`MP.ECHO_SUB_ODDS`, `data/echoes.js`).

### 구현
- `src/services/SpecUpManager.js`: 고정 시드 몬테카를로(mulberry32 + `id|mode|index` 해시, 기본 1500회). 새 에코 = 같은 코스트·주옵·세트, 25레벨, 주옵 최대치.
- 캐시: `id|mode`별, 입력 서명(공통 성장 + 그 모드 에코 칸 + 표본 수 + 서포터 파트너 모드) 단위. 에코가 바뀐 공명자만 다시 계산.
- 화면: 표는 공명자 단위로 나눠 setTimeout(~25ms 조각)으로 점진 계산, 행을 누르면 그 모드·칸으로 프로필 열기. 배지는 렌더 뒤 채움. 「먼저 깎기」 = 기대 상승 0.1% 이상 중 최고 칸, 0.05% 미만은 「교체 효과 거의 없음」.
- 금빛 테두리: `@property --su-a` conic-gradient + 마스크 `::after`, 흐린 `::before` 글로우, `prefers-reduced-motion` 존중.
- 테스트: `tests/specup.test.mjs`(확률표·결정성·ER 게이트·캐시 재계산 횟수 등).
