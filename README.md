# 매트릭스 플래너

명조: 워더링 웨이브 **종말 매트릭스**용 파티 배치 도구입니다.

사이트: https://pjh1998.github.io/matrix-planner/

## 기능

- 보유 공명자만 골라 드래그 앤 드롭으로 3인 파티를 배치합니다. 우클릭하면 해제됩니다.
  터치 화면에서는 공명자를 누른 뒤 빈 슬롯을 누르고, 배치된 공명자를 길게 누르면 해제됩니다.
- 공명자별 배치 횟수(기본 1회, 서포터·긴급 공명자 2회)를 자동으로 계산합니다.
- 이번 주기의 보스 저항·특성, 파워 서킷 수치, 피해 증가 공명자를 함께 보여 줍니다.
- 파티 강도는 다음 순서로 계산합니다. 수치는 `index.html`의 `CHAIN_DATA`, `CHAIN_MUL`, `ROLE_W`, `AMP`, `SYN_BONUS`에서 바꿀 수 있습니다.
  - 캐릭터 점수 = (등급 + 무기 + 재련) × 레벨 배율 × 공명 체인 배율 × 주기 피해 증가. 체인 배율은 [Prydwen](https://www.prydwen.gg/wuthering-waves/characters) Calculations 탭의 체인별 DPS(S0 대비 %)를 캐릭터마다 넣었습니다(`CHAIN_DATA`). 데이터가 없는 캐릭터는 역할별 평균을 쓰고, 서포터는 딜증에 완만한 배율(6체인 120%)을 곱합니다.
  - 메인 딜러는 점수 100%, 서브 딜러는 50%, 서포터는 20%를 파티 피해로 반영합니다.
  - 파수인·벨리나처럼 반주 연결과 관계없이 딜증을 주는 캐릭터는 딜증(%)을 곱합니다.
  - 반주 연결(메인 딜러 대상 조건 1개당 8%), 메커니즘(5%), 추천 조합(5%)을 시너지 보너스로 더합니다(최대 40%).
  - 마지막으로 선택한 파워 서킷을 반영합니다.
- **추천 순서로 정렬**은 보스 진행을 시뮬레이션해서 순서를 고릅니다. 파티는 앞 파티가 남긴 보스 HP를 이어받는다고 가정하고(보스 HP = 파티 평균 강도, 라운드마다 ×1.5), 메인 딜러 속성을 보스가 저항하면 피해를 ×0.6으로 계산합니다. 저항 보스를 만나지 않는 순서를 우선하고, 결과가 비슷하면 약한 파티를 앞에 둡니다. 각 파티에는 예상 상대 보스(vs 1R ○○)가 표시됩니다.
- 다크 모드를 지원합니다. 오른쪽 위 버튼으로 전환합니다.
- 초상화에 마우스를 올리면 반주 스킬 버프, 주력 피해 유형, 메커니즘(합일, 조화 밀집, 서리 효과 등)을 보여 줍니다.
- 파티 안에서 시너지가 맞으면 슬롯 사이에 ✓ 연결 표시가 뜨고, 아래에 근거가 표시됩니다.
  - **반주 → 피해 유형**: 한 캐릭터의 반주 버프가 다른 캐릭터의 주력 피해(일반 공격, 공명 스킬 등)나 같은 속성 피해를 올려 줄 때
  - **메커니즘**: 두 캐릭터가 같은 메커니즘을 쓸 때 (⛓)
  - **추천 조합**: 미리 등록한 조합이 파티에 모두 들어 있을 때 (★)
  - 1번·3번 슬롯끼리 이어지면 파티 번호 아래에 ↺ 표시가 뜹니다.

## 데이터 저장

보유 캐릭터, 성장도, 파티 편성은 **사용하는 브라우저에 자동 저장**됩니다. 서버로 전송되지 않으며, 다른 사람에게 보이지 않습니다.

- 같은 브라우저로 다시 열면 그대로 이어서 쓸 수 있습니다.
- 다른 기기나 브라우저로 옮기려면 **데이터** 탭에서 JSON을 내보낸 뒤, 옮길 곳의 같은 탭에서 가져오기 하세요.
- 브라우저의 사이트 데이터(쿠키 등)를 지우면 함께 지워지니, 중요한 편성은 JSON으로 백업해 두세요.

## 파일 구성

| 경로 | 내용 |
|---|---|
| `index.html` | 사이트 전체 (화면, 공명자·주기 기본 데이터, 로직) |
| `portraits/` | 초상화 이미지 폴더 |
| `scripts/build-portrait-index.mjs` | `portraits/index.json` 생성 스크립트 (배포 때 자동 실행) |
| `.github/workflows/pages.yml` | `main`에 푸시하면 GitHub Pages로 배포 |
| `firebase-config.js`, `firestore.rules` | 사용하지 않음. 나중에 계정 로그인을 붙일 때를 위해 남겨 둔 파일 (아래 참고) |

## 초상화 추가하기

`portraits/` 폴더에 이미지를 넣고 커밋하면 됩니다. 파일 이름은 공명자 **id** 또는 **한국어 이름**으로 맞춥니다.

```
portraits/suoming.webp
portraits/쇄명.png
portraits/방랑자(전도).png
```

세로형 카드 이미지면 위쪽(얼굴) 기준으로 잘려 보입니다. 가로 220px 정도의 webp를 권장합니다.
배포할 때 목록(`index.json`)이 자동으로 만들어지니 직접 고칠 필요는 없습니다.
공명자 id 목록은 사이트의 **데이터** 탭 > 공명자 데이터에서 볼 수 있습니다.

## 배포

저장소 **Settings > Pages > Source**가 **GitHub Actions**로 되어 있으면, `main`에 푸시할 때마다 자동으로 배포됩니다.
배포 후 바로 바뀌지 않으면 GitHub Pages 캐시(최대 10분) 때문이니 Ctrl + F5로 새로고침하세요.

## 주기가 바뀌면

`index.html`의 `DEFAULT_CYCLE`을 고쳐 커밋합니다.

| 항목 | 내용 |
|---|---|
| `bosses` | 보스 이름, 속성 저항(`res`), 특성(`effects`: 유리/주의, 적용 라운드, 상성 태그) |
| `buffs` | 파워 서킷 4종과 수치(`dmg`), 조건(`cond`) |
| `vigor2` | 배치 2회 공명자 id 목록 |
| `emergency` | 이번 페이즈 긴급 공명자 (배치 횟수 +1) |
| `dmgBonus` | 공명자별 피해 증가(%) |

새 공명자는 `DEFAULT_CHARS` 배열에 한 줄을 추가하고, 시너지 정보는 `SYN`에 같은 id로 추가합니다(필드 설명은 코드 주석 참고). 추천 조합은 `COMBOS`에 넣습니다. 시너지 원문은 [encore.moe](https://encore.moe/?lang=ko)의 반주 스킬 설명을 기준으로 했습니다. 사이트의 **주기 설정**, **데이터** 탭에서 JSON으로 먼저 시험해 본 뒤 옮기면 편합니다.

## 나중에 계정 로그인을 붙이려면 (선택)

코드에는 Firebase 구글 로그인 연동이 들어 있지만 `firebase-config.js`가 비어 있어서 꺼진 상태입니다. 다른 기기 간 자동 동기화가 필요해지면 Firebase 무료(Spark) 요금제로 켤 수 있습니다.

1. Firebase 프로젝트를 만들고 Authentication에서 Google 로그인을 켭니다.
2. 승인된 도메인에 `pjh1998.github.io`를 추가합니다.
3. Firestore 데이터베이스를 만들고 규칙 탭에 `firestore.rules` 내용을 게시합니다.
4. 웹 앱을 등록해 받은 `firebaseConfig` 값을 `firebase-config.js`에 넣고 커밋합니다.
